# Skill 安装验收与失败恢复 Change Impact（2026-09-24）

用户流程：在 Project 请求安装 Skill，经现有授权工具获取完整内容后，检查本地 bundle、刷新目录并完成或报告具体缺项；普通观察不能冒充检查，历史 Run 不能冒充当前动作。真实桌面验证以隔离项目重放本次入口文件缺失资源 → 被拒绝 → 补齐 → 检查 → 完成为主线，另验证重复失败与重启恢复。

- **变更：** 现有 Tools 增加只读 `verify_skill`，受限检查项目 Skill 的 frontmatter、可加载性、资源引用和文件清单摘要；不执行外来资源、不下载/解包、不授予权限。显式 list_files 如实列出 Skill 文件，隐式上下文扫描继续渐进披露。Skill 目录在显式发现/加载/检查时刷新项目条目，插件已准入快照保持。
- **验收边界：** 检查产出结构验收回执，绑定本地 bundle 摘要和当前工作区；不能声称来源认证、完整远端仓库镜像或运行效果。含可执行资源的 bundle 还需经现有 run_command 执行针对该 Skill 的检查；不自动执行 SKILL.md 中的命令。修改 Skill 后必须重新检查；无关绿色命令不能代替缺失资源检查。普通代码修改继续使用原验证链，混合任务不能被 Skill 检查整体放行。
- **编排/上下文：** 完成拒绝返回当前动作与具体剩余条件；关键副作用事实跨压缩固定保留。重复拒绝按实际修复/有效检查进展计算，不被重复读文件、改摘要或改 intent 清零。保留必要观察、原始请求、暂停/恢复、未知结果和用户取消优先。
- **影响：** fielora-agent 文件/Skill backend，fielora-core 现有执行、验证、结果与检查点模块，既有模型替身与桌面回归。复用 ToolCall / VerificationReceipt / AgentEvent，无 Schema、Migration、FIPC 或凭据变更，无第二 Runtime/权限/状态库。
- **不变量/兼容：** 限项目路径、拒绝越界/链接逃逸/敏感路径，扫描有界；第三方内容始终 untrusted。保留旧记录读取，旧成功无新证据不自动升级；被拒绝任务仍未完成。回滚源码不删除用户文件或历史回执。
- **验证：** 缺资源、完整 bundle、失效摘要、混合修改、无关检查、路径/链接/大小限制、只读权限、目录刷新、跨压缩写入事实、重复失败/修正后恢复；Cross 与受影响 dev/packaged 桌面流程。真实 Provider/Archify 全功能验收单独标记，不用预设替身冒充。
