# 当前验证评估一致性 — Change Impact

用户流程：项目检查经历目录拒绝、隔离反例、源码修改和暂停恢复后，Agent 能看到确切未决检查，完成已验证范围或明确报告缺口，不反复索取相同成功回执。

沿用 ToolCall/Run/Checkpoint，由一个纯派生评估提供检查身份、状态、完成准入和恢复原因。身份包含实际 cwd、程序和参数；未执行拒绝不进入断言失败集合。当前失败不能被其他命令成功掩盖；仍存在的目标上，旧失败保持待重验。已删除的项目内临时副本成为历史目标，不获得通过；结束仍需当前成功检查。当前版本缺失、检查期间输入变化、未知副作用维持失败关闭。

隔离继续使用项目内临时源码副本及独立数据，现有目录、符号链接、权限和沙箱规则不变。受控反例通过既有 unittest/pytest 外层测试运行子进程，断言注入生效、指定断言失败、没有导入/运行错误；不新增模型自报 expected_failure 的通过开关，不给普通脚本授予验证权限。参数拒绝反馈指出受支持的隔离路径。

CurrentWork、finish_task 和恢复消费同一评估，记录具体阻塞 ID/目标/状态。完成事件继续表达本轮结束，但未知需求覆盖保持 UNKNOWN，不能自动写成 goal_satisfied=true；界面区分检查通过与整体验收。相同检查同输入重复执行不重置结果拒绝计数。

无 Schema/Migration、凭据、权限或 Provider 改动；新字段为现有 JSON 回执/事件的可选元数据，旧记录保留。回滚代码不删除历史证据。工程回归覆盖未启动拒绝、不同 cwd、当前/旧失败、检查中变化、反例外层断言、冷恢复、未知覆盖及错误提示对应关系；真实 Electron 开发/打包宿主运行真实 Python，但确定性模型替身不代表真实模型质量。Coding Plan 仅保留用户交互式验收，原业务项目不代修、不自动续跑。
