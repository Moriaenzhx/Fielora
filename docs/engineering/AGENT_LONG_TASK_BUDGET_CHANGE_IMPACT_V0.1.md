# Long task budget and recovery — Change impact (2026-09-25)

User flow: Settings → Models → Services / Usage / Task budget. Persist device defaults for interactive tasks; snapshot validated limits when a task starts or the user explicitly continues it. Existing running tasks retain their allowance. Defaults remain one accumulated execution hour, 2M input and 65,536 output tokens; configurable ceilings are eight hours, 50M input and 1M output. Time is accumulated model/tool execution, not elapsed waiting or an individual request timeout.

Add optional resource_budget to trusted start/resume requests. Validate in Electron and Rust; persist in existing RunCreated/RunResumed event transactions. Replay those events to restore limits and consumption; legacy events use prior defaults. No schema migration, credentials, model-editable budget tool or second settings/runtime store. Explicit user resume resets consumption under the new grant; automatic recovery never grants allowance. Model/provider content cannot increase limits.

Add bounded receipt-derived recovery attempts and comparisons to existing work checkpoints. Classify failures, retain actual action/input/outcome identities and recommend meaningful alternatives; within an execution segment, block repeated unchanged failed process proposals after three attempts until inputs change, without replaying unknown effects. A continued execution allows fresh attempts (external conditions may have changed), while retaining past evidence and existing budget accounting. This is recovery control, not semantic proof that an alternative will work. Existing no-progress, cancellation, policy, approval and outcome verification remain independent.

Verification: legacy settings and request compatibility; invalid-limit rejection at both boundaries; start/resume/restart accounting with short synthetic events (no hours-long spend); recovery loops versus changed inputs; tab keyboard/navigation and saved preferences; real packaged UI and deterministic Agent integration. Real-model autonomous recovery remains a separate acceptance claim. Rollback removes new request/projection/UI fields while old event payloads remain readable.
