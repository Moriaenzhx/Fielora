# 模型能力与推理配置 — Change Impact

2026-10-02：用户授权实现已讨论的模型能力、有效推理设置和逐项兼容验证。基于现有 Model + Harness + Capability；不增加第二运行时。

- 用户流程：添加服务/模型 → 查看已知/未知能力 → 选择实际支持的推理模式 → 保存 → 文本与 Agent 使用相同配置 → 按需运行有界兼容测试 → 重启后保留设置和分项证据。
- 合约：增量增加模型能力/设置/验证 DTO 与受信 Provider IPC；旧调用继续使用服务默认值。能力区分声明与测试，未知不等于不支持；不因模型名称直接认证任意代理端点。
- 数据：新增 SQLite migration 0017，按 Provider、精确端点、Model ID 隔离设置/测试。旧 schema 16 升级保持身份和内容；旧二进制不得打开升级数据库。配置修改使原设置测试失效，凭据/Provider revision 变化使证据失效。
- Model：参数映射集中在现有 fielora-model；默认不注入推理覆盖。私有 reasoning continuation 只在有界内存消息中保留并按协议回传，不进入 UI、事件、日志、数据库或通用上下文。重启/压缩丢失的协议状态不得伪造；历史事实通过既有恢复上下文继续。
- Harness：既有 L3 调用配置，L4 重试、L6 恢复、L7 权限、L8 验证不变。每个 Run 保留有效设置快照及有界非敏感参数诊断；不自动加大思考量、调用测试或授予权限。
- 验证：声明/未知/端点边界，参数映射及拒绝，不泄露 continuation，真实 HTTP 流式替身的工具回传/纠错/取消，schema16→17 兼容、Core IPC 与 dev/packaged 桌面重启。用户手动发起的兼容测试采用固定无副作用工具与硬时长/输出上限，可取消；测试结果只代表该项目该次测试，不称模型质量认证。
- 回滚：保留旧 profile/本机数据库备份；源码可独立回退，数据只向前迁移。本轮不推送/合并 main，既有 PreMerge 失败独立报告。
